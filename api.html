Quick start

Keep your key in a secret manager or server-side environment variable. Send it in the X-API-Key header; never put it in a URL, screenshot, or commit.

curl -H 'X-API-Key: mk_your_key' \
  https://your-host.example/api/v1/roast

If your key appears in a log, rotate it. The log is not a vault; it is merely a diary with worse access control.

Endpoints

GET /api/health

Unauthenticated service health check. Returns a minimal status response.

GET /api/v1/roast

Requires an API key. Optional mode values are standard and extra-spicy. Responses are drawn from the existing local roast collection.

GET /api/v1/docs

This documentation page, designed to be readable by people and forgiving to keyboards.

Security model

  • API-key authentication accepts headers only and hashes the request identity for diagnostics.
  • Rate limiting slows automated abuse, including bots that mistake every endpoint for an all-you-can-eat buffet.
  • Helmet headers, strict CSP, no-store caching, strict CORS, bounded JSON bodies, and safe text sanitization are enabled.
  • Read-only content endpoints reduce CSRF exposure. If write endpoints are added later, use explicit CSRF protection and same-origin validation.
  • Errors stay deliberately generic so attackers get less useful detail than legitimate operators.

Accessibility promise

This page uses header, nav, main, section, and footer landmarks; a skip link; labelled headings; descriptive code examples; keyboard-operable links; visible focus styles inherited from the site; responsive sizing; and an atomic polite live region for page status.

No modal or custom focus trap is introduced here, so focus follows normal browser navigation and VoiceOver users can move through the document predictably.
